What happens when two browser tabs edit the same product, or a save fails? This Java exercise treats those failures as part of the interface.

Static architecture brief. GitHub Pages cannot run Java. The working application runs locally with a JDK. This page contains illustrated scenarios, not a connected catalog or a simulated backend.

Practical scope

Create, search, edit and delete products. Unique SKU, Unicode names, integer CNY cents and bounded stock. Local file persistence restores records after restart.

Distinct contribution

Project 07 explores in-memory trees. This exercise adds HTTP validation, persistent state and stale-edit rejection. No research novelty or measured business improvement is claimed.

One edit, from form to disk

Browser form → HTTP boundary → record validation + version check → temporary snapshot → atomic replacement → publish memory → redirect

The server binds to 127.0.0.1. A per-process form token, Host/Origin checks and escaped HTML protect the local form boundary. A file lock excludes another opener. Successful writes receive a monotonically increasing revision.

If a snapshot cannot be replaced atomically, the new state is not published in memory. This design is intentionally small; it is not an ACID database or a power-loss recovery guarantee.
